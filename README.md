# BASE · 住宅基础空间母模型

源图：`public/source-plan.png`，1254 × 1254 像素。

## 使用

Viewer 包含透视、正交轴测、正交俯视、独立二维平面和第一人称漫游。三维模式支持旋转 / 平移 / 缩放、空间定位、顶面开关、家具层开关、门扇开关和剖切高度。二维平面使用与模型相同的图纸坐标，可叠加原图。漫游使用 WASD / 方向键、拖动转向及屏幕移动按钮；通过墙体、窗带和家具占位碰撞约束移动。公共楼梯仅为形体示意，不支持跨层行走。

## 空间判读

- 主入户口位于右上玄关与公共前室之间。玄关向左连接餐厅，餐厅向下连接客厅与多功能区。
- 中央过道沿厨房南侧横向展开，向西连接次卧（一）入口和主卧套区入口。主卧套区内部为主卧—衣帽间—主卫的关系。
- 公卫位于厨房西侧，外置洗手干区与中央过道连接。公卫南侧入口按图推定。
- 次卧（二）位于右下，与公共区之间入口位于其西北角；储藏间在该入口上方。
- 厨房保留西、北、南侧操作布置和东侧开口。餐厅为六人桌，南侧岛台 / 餐边台按图占位。
- 客厅与多功能区之间不增加隔墙。沙发布局、床位、柜体和桌椅按原图位置建模，次卧（一）床头朝左，其余两间床头朝右。
- 健身区位于北侧，西连庭院，北侧泳池。玻璃边界和推拉门的形式需要建筑资料复核。
- 右上厚墙方形井道按电梯推定；右侧梯段和小设备间按符号示意。深色粗线视为墙体，局部加厚为柱 / 墙垛占位，不据此判定承重。

## 尺度和可信度

没有尺寸链、比例尺、标高或朝向。坐标统一映射为 0.014 m / 像素，根据常见床长约 2.0 m 的占位估算。整个图示范围约 16.4 × 16.3 m；不是室内净尺寸或建筑面积。墙高 2.8 m、门高约 2.15 m、窗台 0.18 m、窗顶 2.65 m、楼板 0.16 m、泳池深 1.2 m 均暂定。原图上方并不表示正北。

弧形窗带通过细分折线保留图示圆角轮廓。尚未建立未知的梁、管线和真实立面细部。门窗推定项保存在每个 opening 的 `inferred` 字段中，二维检查图用不同线色区分。该模型用于空间复核，非施工图或实测 BIM。

## 模型层级与后续风格替换

- `01_ARCHITECTURE_FIXED`：墙体、柱垛、楼板、顶面、门窗、池体、楼梯占位以及固定卫浴与灶具点位。
- `02_INTERIOR_DESIGN_REPLACEABLE`：完整家具、柜体、台面、器械和庭院家具集合。未来灯具、软装和可替换材质也进入此层。
- `03_REVIEW_ANNOTATIONS`：交通动线等检查辅助信息，不属于设计对象。

`lib/spatial/plan.ts` 保存原始像素坐标、空间功能、房间关系及占位物体参数。`model.ts` 将数据生成独立三维层级，并提供 `replaceDesignLayer(model, factory)` 接口。Factory 返回完整新的设计 Group，可包含外部 GLB 家具、灯具和材质；替换不访问、不重建建筑层。BASE / STYLE 01 / STYLE 02 / STYLE 03 中，后三项当前是明确未创建的方案槽位。

可交付模型位于 `public/BASE-residence-layered.glb`，以米为单位、Y 轴向上，包含完整高度与顶面（Viewer 默认隐藏顶面）。`public/BASE-spatial-definition.json` 为独立空间定义。

## 检查

`node scripts/validate-model.mjs` 生成模型导出并检查：几何坐标有效、稳定 ID 唯一、门洞中心未被实体墙遮挡、主要使用空间从玄关可达，以及整体替换设计层后建筑数据不变。通行检查在 5 像素网格上使用约 0.168 m 半径，考虑静态墙窗和家具占位；平开门按开启的通行状态处理。门扇关闭时 Viewer 增加门叶阻挡。

此次没有执行浏览器视觉 / 交互自动化检查。页面在支持 `document.modelContext` 的环境中注册 `read_spatial_model` 与 `configure_spatial_view`，当前环境没有可用的 WebMCP 合约验证上下文，因此这部分未验证；常规 Viewer 不依赖该接口。

开发：`npm run dev`；构建：`npm run build`。
