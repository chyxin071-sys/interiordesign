# 可复用的住宅空间设计 Viewer 工作流

这套工作流适合把一张住宅平面图发展为“固定建筑空间 + 可替换室内设计层 + 可漫游 Viewer”。核心原则是先锁定建筑事实，再生成可替换的设计方案，最后把检查、编辑和发布做成同一套交互系统。

## 1. 输入整理与空间识别

先保存原始平面图和所有参考图，建立版本号。对平面图做结构化识别：外墙、内墙、柱垛、门洞、窗洞、房间边界、空间功能、家具占位、室内外边界和主要交通路径。对无法确认的尺寸、标高、朝向和结构性质单独列为“推断”，不要把推断混入已确认事实。

识别结果应输出为可查询的数据，而不是只停留在视觉描述中。建议至少包含：稳定 ID、几何点列、厚度、高度、所属空间、开合方向、固定或可替换标记、参考来源和置信度。

## 2. Base Architecture 建模

先只建立建筑母模型：墙体、柱垛、楼板、顶面占位、门窗、固定卫浴、楼梯、室外平台和泳池边界。庭院、泳池和健身平台要先判断是否露天，再决定是否有顶面或围护；不能因为平面图中出现阴影或玻璃质感就自动封闭室外空间。

Base Architecture 一旦确认，应使用稳定坐标、稳定 ID 和几何指纹。所有 Style 只引用这套建筑层，不能在方案切换时复制或改写墙体、门窗和主要交通关系。

原图无尺寸时，先用一个明确的像素到米比例，再用床、门和常见通道宽度做交叉校正。把比例、墙高、门高、窗台、楼板厚度和推断依据写入项目文档，方便后续替换成实测数据。

## 3. Interior Design Layer 设计层

每个方案独立生成一套设计层，并使用独立的资产 ID。方案差异应来自家具几何、布局、尺度、灯具、柜体、软装、材质和灯光组合，而不是只替换颜色。

建议每件可移动资产都是独立的 `Group`，带有 `room`、`kind`、`style`、`variant`、`replaceable` 等元数据。家具、灯具、窗帘、地毯、艺术品、植物和户外家具都属于设计层；墙体、门窗、固定卫浴和池体属于建筑层。

## 4. 交互 Viewer

Viewer 同时提供整体浏览和空间检查：Perspective、Axonometric、Top、2D Plan、Walkthrough、Orbit、Pan、Zoom、顶面开关、墙体剖切、房间目录、动线和门扇状态。

固定空间机位以空间为索引保存，切换 Style 时保留当前空间和镜头。这样同一个客厅机位可以直接比较 BASE、STYLE 01、STYLE 02 和 STYLE 03。

白模应作为 Display Mode，而不是 BASE 的专属材质。建议至少提供 ARCTIC、SHADED、MATERIAL 三种显示方式，并把环境光、主光方向、光线高度、阴影强度、AO 和轮廓强度做成少量可理解的控制项。

## 5. 家具编辑交互

点击家具后再显示操控器，点击空白处隐藏操控器。操控器必须绑定到当前家具的几何中心或编辑枢轴，不能直接使用错误的父组原点。

移动模式只开放水平移动；旋转模式只开放绕竖直轴的平面旋转，避免家具被拖到空中或绕 X/Z 轴翻转。自由旋转和角度吸附要分开：自由旋转用于微调，Shift 可吸附 15°，Ctrl 可吸附 45°。所有变换都进入 undo/redo 快照，Ctrl+Z 撤回，Ctrl+Y 恢复，Esc 取消选择。

## 6. 验证顺序

先验证建筑层：有效几何、稳定 ID、墙体连续性、门窗开口、室内外关系和主要空间可达性。再验证设计层：三套方案是否真的更换了几何、是否覆盖全屋、是否有穿墙或阻断主要通道、固定机位是否仍可用。

最后再做性能检查：网格数量、三角面数、材质数量、初次加载时间和交互帧率。优先保持资产组可选和可移动，再对未编辑的静态几何做批处理；不要为了减少网格而把所有家具合并成一个不可编辑网格。

## 7. 发布与版本管理

每个可交付版本都应记录：源图版本、Base Architecture 版本、方案版本、Viewer 版本、验证结果和发布地址。先本地类型检查和生产构建，再生成发布包，确认包来自当前提交，最后保存版本并部署。发布后用强制刷新检查资源是否更新，并保留上一版可回退。

## 8. 可继续优化的方向

下一步最有价值的是把当前程序化家具逐步替换为可复用的资产库，并引入更明确的“资产选择、局部锁定、吸附到墙、复制、删除、恢复初始布局”操作。建筑层可以进一步接入 Rhino、Blender 或 Revit 的真实模型导入，使用 GLB/USD/glTF 作为中间格式；Viewer 继续负责方案切换和比较。

更专业的插件形态可以分成三层：建模软件插件负责平面图解析、精确几何和资产编辑；共享数据层负责稳定 ID、空间语义和方案差异；Web Viewer 负责轻量预览、镜头比较和团队评审。这样能同时获得专业软件的建模精度和浏览器 Viewer 的快速分享能力。

插件化时应优先解决坐标系统、单位、材质映射、门窗语义、资产 GUID、增量同步和撤销栈一致性。不要先做复杂渲染；先保证建筑边界、家具几何、编辑行为和版本回退可靠，再增加实时渲染或离线效果图。
